Agentic Payment Firewall - System Flow

Technical routing paths, APIs, hook triggers, and consent escalation loops in Razorpay.

Evaluation Pipeline Routing Flow

01

Checkout Pre-Flight Gate

Instead of routing checkout directly to payment servers, the AI agent passes details (`ProposedTransaction`) to the APF API endpoint `/v1/transactions/evaluate`.

02

Ensemble Evaluation

The transaction details flow simultaneously to the Policy Filter, the Intent Word/Embedding Sim Matcher, Context Injection Guard, and session sequence counters.

03

Risk Aggregator Scoring

A single index value (0.0 to 1.0) is formed by combining evaluation signals. Decision limits direct action: APPROVE / CHALLENGE / BLOCK.

ON APPROVE
Direct Razorpay Execution

Transaction risk score < 0.30. Core server constructs UPI Reserve Pay order ID. Mandate limit decremented. Quick 80ms completion.

ON CHALLENGE
Stepped Consent Escalation

Borderline metrics (0.30 to 0.70) trigger push-notification. Mobile overlay highlights authorized mandate text alongside checkout values side-by-side. Approve releases transaction; decline aborts.

ON BLOCK
Evasive Action Rejected

Risk score ≥ 0.70. Core transaction ends with error. Context trace logged to retrain embedding models. Agent is given details to inform user.

Razorpay Integration points

  • UPI Reserve Pay Hook: Syncs client grants directly with the Reserve Pay authorization schemas. Ensures limit configurations match double-entry balances.
  • Auditable Logs & Retraining Loop: Every transaction decision logs embeddings and logs. Overrides and disputes automatically mark files for scheduled nightly system weight updates.
  • Context Diffs: Uses LLM-as-a-judge or Sentence Transformers to comparison-scan the starting instruction against final action descriptions, blocking prompt hijacking.
